## 2. 학습 내용 및 실습

### 2-1. 프로세스

1. 프로세스 : 실행 중인 프로그램, PCB를 지닌 프로그램이다. 실행 시 번호 (PID)가 할당되어 관리된다.

<br>

2. 프로세스 구분 : 프로세스는 백그라운드와 포어그라운드로 구분된다. 보통 쉘에서 명령어를 실행하면 포어그라운드로 동작하여 해당 프로세스가 종료될 떄까지 대기한다.

* 백그라운드 프로세스 : 사용자의 입력에 관계없이 실행된다.
* 포어그라운드 프로세스 : 명령 입력 후 수행 종료까지 기다려야 한다.
* 명령어 실행 시에는 주로 포어그라운드로 동작하지만 끝에  '&' 문자를 붙여주면 백그라운드로 동작한다.

<br>

3. 멀티 태스킹과 작업 전환

* bg 명령어 : 포어그라운드 -> 백그라운드로 전환
* fg 명령어 : 백그라운드 -> 포어그라운드로 전환 ( 다수의 작업이 백그라운드 프로세스로 동작 중일 경우 jobs 명령어를 통해 원하는 프로세스의 작업번호를 이용하여 전환 가능 -> fg % 작업번호 또는 fg 작업번호 )
* jobs 명령어 : 백그라운드로 실행중인 프로세스나 현재 중지된 프로세스의 목록을 출력

<br>

4. 프로세스 구분 : jobs 명령어 결과 중 +과 -의 차이

* '+' : 주로 처리되는 프로세스를 뜻하며, 사용자가 가장 늦게 실행한 프로세스. fg명렁어를 작업번호 없이 수행하면 + 되어 있는 작업이 포어그라운드 프로세스로 전환됨. 
* '-' : + 기호 작업의 다음 우선순위의 작업

![alt text](<image/스크린샷 2026-10-21 오후 6.44.23.png>)

5. 프로세스 생성 방법 : fork와 Exec 방식이 있다.

* fork : 새로운 프로세스를 위해 메모리를 할당 받아 복사본 형태의 프로세스를 실행하는 형태. 기존의 프로세스는 그대로 실행되고 새롭게 생성된 프로세스는 기존 프로세스와 같은 코드를 기반으로 실행됨. 부팅 시 실행되는 최초의 프로세스 init 프로세스는 PID 1번을 할당 받고 시스템 운영에 필요한 그 외의 프로세스는 fork되어 init 프로세스의 자식 프로세스로 생성됨.

<br>

* Exec : 원래의 프로세스를 새로운 프로세스로 대체하는 형태. 호출한 프로세스의 메모리에 새로운 프로세스의 코드로 덮어씌워짐.

<br>

* fork와 Exec의 차이 : 보통 명령어 실행의 경우 사용자가 로그인 후 bash 프로세스를 할당 받고 그 아래로 fork 되어 수행됨. 명령어 앞에 exec를 붙이고 사용하면 기본 프로세스가 교체되면서 새로운 프로세스를 할당.

<br>

* pstree 명령어를 이용하여 init 프로세스 확인

<br>

6. 시그널(Signal) : 프로세스끼리 서로 통신할 떄 사용되는 신호이다. 즉, 특정 프로세스가 다른 프로세스에게 메세지를 보낼 때 시그널을 이용한다.

* 시그널 발생 요인 : 사용자가 인터럽트 키를 통해 발생하는 시그널, 프로세스가 발생하는 시그널, 하드웨어가 발생하는 시그널 등 다양하게 발생한다.

* 시그널 목록 : kill -l 명령어를 통해 시그널 목록을 확인할 수 있다.

<br>

### 2-2. 데몬

1. 데몬(Deamon) : 사용자가 직접적으로 제어하지 않고, 백그라운드 영역에서 실행되며 리눅스의 주요 기능들을 구동하는 작업을 하는 프로그램이다. 

<br>

* 데몬은 보통 이름 끝에 'd'를 달고 있으며, 일반적인 프로세스로 실행된다. ( ex - 'syslogd', 'sshd' 등 )

<br>

* 데몬은 대개 부모 프로세스를 init 프로세스로 가지며 (PPID가 1), 자식 프로세스를 포크 (fork) 하여 생성된다.

<br>

2. 데몬의 분류 : 실행 방식에 따른 분류

* Stand-alone : 자기 스스로 시스템에 상주하여 클라이언트 요청에 보내주는 방식 -> 빠른 응답과 처리를 하기 위한 것으로 데몬이 독립적으로 존재함.
* (x)inetd : 시스템 부하를 줄이고자 inetd 데몬을 이용하여 일괄 관리를 한다. 서비스 요청이 들어올 경우에만 관련 프로세스를 수행시키고 자동으로 종료시키는 방식이다. 

<br>

3. 데몬 관리 : /etc/rc.d/init.d 디렉터리

* 데몬의 효율적인 관리를 위해, 부팅과 관련된 정보는 /etc/rc.d 디렉터리에 모아두고, 관련된 데몬들은 init.d 디렉터리와 rc0.d ~ rc6.d 디렉터리를 이용하여 실행을 조절하는 방식이다.

<br>

* 인자 : start, stop, restart, status, reload 등 -> ex) /etc/rc.d/init.d/start

<br>

4. 데몬 제어 명령어

```bash
$ service [데몬명] [start|stop|restart]
```
* /etc/rc.d/init.d 디렉터리에 존재하는 스크립트를 쉽게 시작하거나 중지시킬 수 있는 스트립트로, 절대경로로 전부 입력하는 대신에 간단히 데몬명과 인자값을 지정해서 실행한다.

<br>

```bash
$ /etc/init.d/  [데몬명] [start|stop|restart]
```
*  /etc/init.d/ 디렉터리는 /etc/rc.d/init.d 로 심볼릭 링크가 걸려있어, /rc.d/ 명을 생략해서 사용 가능하다.

### 2-3. 프로세스 제어

1. 프로세스 우선순위

* PRI : 운영체제에서 참고하는 우선순위 값으로, 낮은 값일 수록 우선순위가 상위이다. 사용자나 root가 조작할 수 없고 시스템 상황에 따라 적절히 부여된다.

* NI : 낮은 값일 수록 우선순위가 높고, root만이 값을 낮출 수 있다. NI 값을 설정하면 리눅스는 상황에 따라 PRI 값을 적절히 변경하여 우선순위를 조정한다.

![alt text](<image/스크린샷 2026-11-06 오후 4.19.04.png>)

<br>

2. /proc 디렉터리 : 새로운 프로세스가 생성되면 /proc 디렉터리 안에 PID와 동일한 서브 디렉터리가 생성되고, 그 안에 해당 프로세스에 관한 정보가 저장된다.

![alt text](<image/스크린샷 2026-11-06 오후 4.29.03.png>)

* /proc/PID : 특정 프로세스 내부 구성을 할 수 있다. 그 안에 해당 프로세스에 관한 정보가 저장된다.

```bash
$ ls /proc/7100  # 예시
```

### 2-4. 프로세스 스케줄링

1. cron : 유닉스 계열 컴퓨터 운영체제의 시간 기반 작업 스케줄러이다. 고정된 시간, 날짜, 간격에 주기적으로 실행할 수 있도록 스케줄링을 수행한다.

* 보통의 경우 /etc/crontab 파일에 의해 구동된다.
* 총 7개의 필드로 구성된다. (분, 시, 날짜, 월, 요일, 사용자, 명령)

![alt text](<image/스크린샷 2026-11-06 오후 4.39.25.png>)

* 옵션 -l : crontab에 설정된 내용 출력
* 옵션 -e : crontab의 내용을 작성하거나 수정

<br>

2. cron 사용자 제한 : 해당 파일들 내에 사용 허가 또는 사용 제한을 지정하고 싶은 사용자명을 삽입한다.

* /etc/cron.allow : crontab 명령어 사용 허가 파일
* /etc/cron.deny : crontab 명령어 사용 제한 파일

<br>

* 두 파일이 모두 존재할 경우 cron.deny에 사용자명을 넣어 제한을 걸어도, cron.allow에 사용자명이 있다면 해당 사용자 사용이 가능하다.

* cron.deny 파일만 존재할 경우, cron.deny에 사용자명을 넣어야 해당 사용자 제한이 가능하다.

* cron.allow 파일이 존재하는 경우, cron.deny 파일 존재 여부에 상관없이 cron.allow 파일에 사용자명을 넣어야 해당 사용자 사용이 가능하다.
